The Key Never Leaves

The agent runtime executes model-authored code, so it is treated as hostile. It is never given ARK_API_KEY. It receives a scoped, 10-minute session token and calls back through a host-side reverse proxy, which is the only line of code that ever writes the real key onto a wire.

FIG 1

Where the secret sits, and what crosses each boundary

Four zones, four crossings. The orange path is plaintext ARK_API_KEY and it exists only inside the host and on the hop to Ark. Everything the container holds is green: a revocable ast_ token that buys four endpoints for ten minutes.

FIG 2

The swap: four gates between a session token and the real key

B3 is the load-bearing boundary. Order matters — a rejection at gate 2 means step 5 never runs, so a stolen or expired token never reaches the code that holds the key. Four gates gate the swap; steps 5 and 6 are the swap itself, and the code assembles the key-bearing header before it touches the body.

FIG 3

Token lifetime and the three ways it ends

The session token is the whole reason the container can work without the key, so its window is the thing to keep short. Three independent paths close it, and none of them depends on the agent behaving.

NOTE

Four things the diagram would overstate if drawn as designed

These are read from the wiring, not the intent. Each is a control that exists and is tested, but is not on the live path.

Restricted egress is not enforced

validateDestination and inspectCommandEgress implement a full allowlist with IMDS and private-range blocking, including hex, octal and decimal IPv4 canonicalization. Neither is called at runtime. Only buildContainerNetworkArgs runs, and in restricted mode it emits plain --network bridge — the same as bridge mode.

egress-network-filter.ts — reachable only from tests

The IP rate limiter is never registered

registerRateLimiter provides per-IP limits of 300/min general and 30/min on auth, with RateLimit-* headers. createApp never calls it. The only live limit is the per-agent 3/60 s on the messages route, which does not slow bearer-token guessing at B1.

rate-limiter.ts — exported, unused

The proxy logs full prompt bodies

Gate 5 logs { targetUrl, bodyPayload } at info. That is the entire sanitized request — prompts, instructions, and whatever the workspace put into context — written to logs without passing the outbound DLP that guards every other exit.

llm-proxy.ts — "LLM proxy forwarding payload"

B1 does not stand in front of the proxy

The callback route is served by the same listener as the public API, on the same port, and createApp exempts /api/internal/llm-proxy/ from both the bearer hook and the CSRF guard. With the default HOST=0.0.0.0 it is reachable from anywhere the API is. Fig 1 places it inside the host zone, but nothing at B1 guards it — the ast_ token is the entire control.

app.ts — onRequest exemption · config.ts — HOST default
